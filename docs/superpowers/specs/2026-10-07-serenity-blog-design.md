# Serenity · 个人博客 —— 设计文档

- 日期:2026-10-07
- 状态:待评审
- 路径:`serenity/`

## 1. 目标

做一个**属于自己的**个人博客/写作平台:安静、干净、完全自己掌控。

- 用途:写作平台,公开给中文读者
- 作者情况:有编程经验、不熟悉前端;能读懂并维护普通 JS 代码
- 文章以 Markdown 文件的形式写在仓库里,不用任何后台

**成功标准**

- 写一篇新文章 = 新建一个 `.md` 文件 + `git push`,网站自动更新
- 本地一条命令构建(`node build.js`)、一条命令预览(`node serve.js`)
- 访客体验:按时间浏览、按标签浏览、RSS 订阅、亮/暗主题切换、手机上看也舒服

## 2. 范围

**v1 做**

- 首页文章列表、文章页、标签总览、标签页、关于我、RSS、404
- 亮/暗主题切换(跟随系统 + 手动切换 + 记忆选择)
- 本地构建与预览脚本、自动测试、Vercel/Netlify 部署配置

**v1 不做(记录在案,以后再议)**

- 评论、站内搜索、浏览量统计、代码语法高亮、图片自动优化、首页分页、多语言、系列文章

## 3. 技术选型

| 项目 | 选择 | 理由 |
|---|---|---|
| 运行时 | Node.js 24(本机已装) | 环境现成;自带测试运行器与 `--watch` |
| 框架 | 无 | 目标就是"属于自己的网站",几百行自研代码完全可控 |
| 唯一运行时依赖 | `markdown-it` | Markdown 渲染从零写不现实,选最主流、最稳的 |
| 模板 | JS 模板字符串 | 不引入模板引擎,页面结构一眼看懂 |
| 本地预览 | `serve.js`(基于 `node:http`) | 约 30 行,零依赖 |
| 测试 | `node --test` | Node 24 内置,零额外依赖 |
| 部署 | Vercel / Netlify(二选一) | 连接 GitHub 仓库自动构建发布,免费档足够 |

全部依赖只有 `markdown-it` 一个。front-matter 解析、模板、RSS 生成均为自研(各几十行)。

## 4. 目录结构

```

├── posts/                  # 文章:一篇 = 一个 .md 文件(日常只碰这里)
├── about.md                # "关于我"页面的内容
├── site.config.js          # 站点配置:标题、简介、作者、网址
├── src/                    # 构建器代码
│   ├── build.js            #   主流程:读取 → 渲染 → 输出
│   ├── frontmatter.js      #   front-matter 解析与校验
│   ├── markdown.js         #   markdown-it 封装、摘要截取
│   ├── templates.js        #   所有页面的 HTML 模板
│   └── rss.js              #   RSS 生成
├── static/                 # 原样复制到站点根目录
│   ├── style.css           #   全站样式(亮/暗两套 CSS 变量)
│   ├── theme.js            #   主题切换逻辑
│   ├── favicon.svg         #   鼠尾草绿 "S" 图标
│   └── avatar.jpg          #   头像(先用占位图,日后自行替换)
├── serve.js                # 本地预览服务器
├── test/                   # 自动测试
│   ├── *.test.js
│   └── fixtures/           #   测试用示例文章
├── vercel.json             # Vercel 部署配置

├── package.json
├── .gitignore              # 忽略 node_modules/ 与 dist/
└── docs/                   # 本设计文档等
```

## 5. 内容模型

每篇文章 = `posts/` 下的一个 `.md` 文件,文件开头是 front-matter:

```markdown
---
title: 文章标题
date: 2026-10-07
tags: [生活, 随笔]
summary: 一句话摘要(可选)
draft: false
---

正文……
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `title` | ✅ | 文章标题 |
| `date` | ✅ | `YYYY-MM-DD`,用于排序与显示 |
| `tags` | ❌ | 数组,如 `[生活, 随笔]`;也可写单个字符串 |
| `summary` | ❌ | 列表页摘要;不写则自动取正文前 ~60 字(去除 Markdown 标记) |
| `draft` | ❌ | `true` 时本次构建完全跳过,并在终端提示"已跳过草稿: <文件名>" |

- **slug(网址)**:文件名去掉 `.md`,`posts/my-first-post.md` → `/posts/my-first-post/`。建议用英文或拼音,中文可用但网址会变成百分号编码
- **排序**:按 `date` 倒序,同日按文件名排
- **关于我**:根目录 `about.md`,front-matter 可省略(标题固定为"关于我")

## 6. 页面与路由

| 页面 | 路径 | 内容 |
|---|---|---|
| 首页 | `/` | 全部文章:标题、日期、标签、摘要 |
| 文章页 | `/posts/<slug>/` | 标题、日期、标签、正文、底部"上一篇 / 下一篇"导航 |
| 标签总览 | `/tags/` | 所有标签 + 各自文章数 |
| 标签页 | `/tags/<标签>/` | 该标签下的文章列表(标签按 URL 编码) |
| 关于我 | `/about/` | 渲染 `about.md` |
| RSS | `/rss.xml` | 全部文章,全文输出 |
| 404 | `/404.html` | "找不到页面,回首页" |
| favicon | `/favicon.svg` | 鼠尾草绿的 "S" 圆角方块 |

每页公共部分(所有页面一致):顶部一个圆角方形 "S" logo + "Serenity" 字样,导航(文章 / 标签 / 关于),右上角主题切换按钮;底部一行版权与 RSS 链接。

## 7. 构建流程

`node build.js` 依次:

1. 读 `site.config.js`
2. 扫描 `posts/*.md`:解析 front-matter → 校验 → `markdown-it` 渲染正文
3. `draft: true` 的文章跳过并提示
4. 生成各页面:首页、每篇文章页、标签总览、每个标签页、关于我、404、`rss.xml`
5. 复制 `static/` 到 `dist/`
6. 打印统计:共 N 篇文章、M 个标签、输出到 `dist/`
7. 构建耗时应在 1 秒内

**错误处理原则**:任何数据问题都让构建**显式失败**(打印出是哪个文件的什么问题、退出码 1),绝不静默猜测修正后发布。

- 缺 `title` / `date`,或日期不是 `YYYY-MM-DD` → 报错并列出文件名与字段
- front-matter 格式损坏(缺少上下 `---`)→ 报错并指出文件
- 标签为空数组 → 视为无标签,不算错误

## 8. 视觉设计(已在浏览器中确认)

- 方向:**现代柔和** —— 浅灰底 + 白色圆角卡片
- 点缀色:**鼠尾草绿**
- 字体:`system-ui, "Segoe UI", "Microsoft YaHei"`,不要外部字体(保证国内加载速度)
- 正文排版:约 17px / 行高 1.8 / 阅读宽度约 680px;中文标点正常渲染

**亮色**:页面底 `#f4f6f8` · 卡片 `#ffffff` · 主文字 `#1b1f24` · 次要 `#6d7783` · 点缀 `#5f7a56`(正文用)/ `#78926f`(色块用)
**暗色**:页面底 `#15181c` · 卡片 `#1d211c` · 主文字 `#e2e6ea` · 次要 `#9aa4a0` · 点缀 `#9db392`

**主题切换**

- 首次访问跟随系统 `prefers-color-scheme`
- 点按钮切换,选择存入 `localStorage`,之后以记忆为准
- `<head>` 内联一行脚本,在页面渲染**之前**设置 `data-theme`,避免"闪白"

## 9. 测试策略

**单元测试**(`node --test`):

- front-matter:正常解析、缺字段、数组标签、引号包裹、非法日期
- 摘要截取:去除 Markdown 标记、长度正确
- 标签聚合:去重、计数
- RSS:XML 特殊字符转义、绝对链接、日期格式
- URL 编码:中文标签生成正确路径

**冒烟测试**:用 `test/fixtures/` 的示例文章在临时目录跑完整构建,断言首页、文章页、标签页、`rss.xml`、`404.html` 均已生成且含预期内容。

**手动检查**:`node serve.js` 后在浏览器看亮/暗切换、窄屏(手机宽度)效果。

## 10. 部署

1. `serenity/` 初始化为 git 仓库,推送到 GitHub(仓库名建议 `serenity`)
2. Vercel 或 Netlify 里选"Import Git Repository",连接到该仓库
   - 构建命令:`node build.js`
   - 发布目录:`dist`
   - 仓库里已含 `vercel.json` / `netlify.toml`,基本零配置
3. 以后每次 `git push` 自动重新发布
4. 可选(以后):绑定自定义域名
